## Aplicação do seed

Confirmar o project-ref ANTES de qualquer comando:

```
cat supabase/.temp/project-ref
# deve mostrar: tljscgsaqofgrfbjuyif
```

Se não mostrar `tljscgsaqofgrfbjuyif`, ligar explicitamente ao HML:

```
supabase link --project-ref tljscgsaqofgrfbjuyif
```

Aplicar o seed (transacional — aborta sozinho se algo não bater):

```
supabase db query --linked -f supabase/checks/sprint_5_1_1_gifts_seed_hml.sql
```

O script tem **proteção contra reaplicação duplicada** — não é
idempotente por design: se os dados de teste já existirem (mesmo prefixo
ou mesmo UUID fixo), ele aborta antes de inserir qualquer linha, em vez de
duplicar ou sobrescrever. Se abortar por esse motivo, rodar o rollback
(seção "Rollback" abaixo) antes de tentar de novo.

Conferir a saída das três consultas de verificação no final do script
contra a seção "Resultado esperado" do próprio arquivo.

## Smoke vendedor

No Autoatendimento (`/atendimento` → "Brinde para cliente"), logado como
perfil `vendedor`, testar cada cenário com os brindes/kits
`HML TESTE 5.1.1 - ...`:

- item disponível (`Item Avulso Disponivel`, saldo 10);
- item sem saldo (`Item Avulso Sem Saldo`, saldo 0 — deve bloquear);
- kit válido (`Kit Valido (2 disponiveis)` — deve permitir até 2 entregas);
- kit sem componentes (`Kit Sem Componentes` — opção desabilitada, motivo
  "sem itens cadastrados");
- kit com componente inativo (`Kit Com Componente Inativo` — opção
  desabilitada, motivo "item inativo");
- kit sem estoque da feira (`Kit Sem Estoque Na Feira` — opção
  desabilitada, motivo "sem carga nesta feira");
- kit com saldo insuficiente (`Kit Com Saldo Insuficiente` — opção
  desabilitada, motivo "saldo insuficiente");
- troca rápida entre DUAS feiras: **N/A nesta rodada** — HML possui
  somente `Feira Teste`, então concorrência/limpeza de seleção entre duas
  feiras distintas não é testável manualmente aqui e não deve ser
  registrada como validada. Não afirmar que este caso foi coberto;
- limpeza de seleção ao remover/reselecionar a MESMA feira (se a interface
  do Autoatendimento permitir desmarcar e escolher a `Feira Teste`
  novamente): confirmar que um brinde/kit já selecionado é limpo e que o
  saldo é recarregado — este teste cobre a limpeza de estado, mas não a
  proteção contra resposta obsoleta entre feiras diferentes, que
  permanece validada apenas por revisão de código (`saldoRequestRef`);
- duplicidade (registrar o mesmo cliente/empresa duas vezes na mesma feira
  e confirmar o aviso de possível duplicidade antes de liberar de novo);
- atualização do saldo após entrega (entregar o `Kit Valido` uma vez e
  confirmar que a disponibilidade cai de 2 para 1 sem precisar recarregar
  a página).

## Rollback

Confirmar o project-ref ANTES de executar (mesmo comando do passo acima).

```
supabase db query --linked -f supabase/rollbacks/sprint_5_1_1_gifts_seed_hml_rollback.sql
```

Idempotente — pode ser executado mais de uma vez sem erro.

## Validação após rollback

As seis consultas finais do próprio script de rollback devem retornar
todas `0`:

- `brindes_teste_restantes` → 0
- `kits_teste_restantes` → 0
- `componentes_teste_restantes` → 0
- `estoque_teste_restante` → 0
- `entregas_teste_restantes` → 0
- `itens_entrega_teste_restantes` → 0

Qualquer valor diferente de `0` indica que o rollback não terminou de
limpar os dados de teste — não prosseguir para Produção até investigar.
